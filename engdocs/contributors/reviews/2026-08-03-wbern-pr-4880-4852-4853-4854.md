## Decision summary

### #4880: approve, with a tracked hardening follow-up

The performance premise holds. The cache inputs are embedded, immutable data,
and the removed per-pack walk is covered by the union walk. The final head is
unchanged from the reviewed head, and required CI passed.

One test still claims more than it proves. Both calls in
`internal/builtinpacks/registry_test.go:573-585` return the same memoized map
headers from `internal/builtinpacks/registry.go:555-576`; comparing their lengths
cannot detect bad cached content. The production helper also returns the
process-global allowlist maps directly at `registry.go:563-565`, leaving the
validation boundary open to package-local mutation. This does not invalidate the
current optimization because the sole caller only reads the maps
(`registry.go:512-545`), but it weakens the guard against future changes.

Follow-up: `gc-8fx8z.2.3`.

### #4852: approve

The original version could accept `lsof` error annotations as paths and could
treat timeout-truncated output as authoritative. Commit
`9faedd64c57c4e64a5a43ac605240138ec34c7f2` fixed both:

- `cmd/gc/bead_worktree_liveness_fallback.go:40-45` routes the probe through the
  package's hardened `lsofOutputWithTimeout` path.
- `bead_worktree_liveness_fallback.go:47-53,95-103` rejects the absolute-looking
  error annotations found in `n` fields.
- `bead_worktree_liveness_fallback.go:82-86` fails closed on a deadline.
- The fixup adds focused tests for mixed annotations, annotation-only output,
  and timeout behavior.

The final head passed required CI, the resource census, Mac summary, and all
three phase-2 model checks. No surviving merge blocker remains.

### #4853: request changes; fix now tracked after merge

The main fix is correct. Off Linux, `AliveWithCmdline` now checks argv identity
instead of treating every live PID as the expected poller. The final fixup added
`-ww` to prevent width truncation, exercised `psCmdline` directly on Linux CI,
and brought the resource-census policy files into sync. Required and Mac CI
passed.

The parser still loses argument boundaries. `internal/pidutil/pidutil.go:292-315`
uses `strings.Fields` on `ps` output and the comment limits the caveat to session
names and targets. The actual matcher also compares `--city` against an arbitrary
filesystem path (`internal/nudgepoller/poller.go:19-41,107-120`). A city path
containing spaces can never match on the fallback path. Both callers then report
the live poller absent (`cmd/gc/cmd_nudge.go:2600-2622` and
`internal/session/submit.go:644-666`) and may start another poller.

This is a major portability regression with a concrete user input and caller
path. It should have blocked the final head. Since the PR is merged, the fix is
tracked as `gc-8fx8z.2.1`.

### #4854: request changes; performance fix now tracked after merge

The identity fix is behaviorally sound in the normal path. `StartTime` now falls
back to `ps -o lstart=`, the final branch adds a direct success-path test, fixes
the stale Darwin comments, removes the duplicate resource-heavy test, and merges
#4853 before landing. Required CI, Mac CI, and both Claude/Codex/Gemini phases
passed.

The final implementation performs the expensive identity probe inside the reap
poll. `internal/runtime/proctable/kill_unix.go:22-39,71-97` calls
`AliveWithStartTime` every 25 ms for up to the three-second reap grace. On macOS,
`AliveWithStartTime` first runs the `Alive` `ps` probe and then runs the new
`psStartTime` probe (`internal/pidutil/pidutil.go:101-112,263-289`). The slow
path can therefore start roughly twice as many `ps` processes as before, in the
same process-churn scenario the PID-reuse guard addresses.

The identity should be checked once at the decisive boundary, or cached so the
tight liveness loop stays cheap. This is a major operability risk, now tracked as
`gc-8fx8z.2.2`.

   `c33fd2de4f8f69dfb073575dc987ddebdc2b5f43` and preserves both helpers.

#4852 has no textual dependency on the pidutil pair. Its overlap is conceptual:
it adds another process-introspection path, using `lsof` rather than `ps`.
